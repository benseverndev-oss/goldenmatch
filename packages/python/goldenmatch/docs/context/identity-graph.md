## Identity Graph (v2.0, 2026-05-12)

`goldenmatch/identity/` exposes a durable graph layer above run-local clusters: stable `entity_id` (UUIDv7) per identity, source-record nodes, evidence edges, append-only event log, and aliases. SQLite default at `.goldenmatch/identity.db`; Postgres optional.

- **Pipeline hook**: `pipeline.py::_resolve_identities()` runs after clustering, before output, gated on `config.identity.enabled`. Identity is additive — failure logs + skips, never blocks dedupe output.
- **Stable IDs across runs**: derived via `resolve_clusters()` overlap detection, NOT content hash. New cluster -> new id; overlap with one existing identity -> absorb; overlap with multiple -> merge (winner = most members; tie-break oldest `created_at`).
- **Record id**: `{source}:{source_pk}` when `identity.source_pk_column` is set; otherwise `{source}:hash:{12 hex}` from payload SHA-256. Document the no-PK case to users — near-duplicate raw rows can collide.
- **Idempotency**: replaying the same `(run_name, entity_id, kind)` is a no-op via `has_run_event()`; `evidence_edges` has UNIQUE(entity_id, record_a_id, record_b_id, run_name).
- **Surfaces**: Python (`goldenmatch.identity.*` + root re-exports), CLI (`goldenmatch identity list/show/resolve/history/conflicts/merge/split`), REST (`/api/v1/identities/...`), web "Identities" tab, MCP (`identity_*` × 6 tools), A2A (6 skills), TS edge-safe core (`InMemoryIdentityStore` + `query.ts` helpers). TS persistent SQLite backend + pipeline-driven population are v2 follow-ups.
- **Postgres surface**: `goldenmatch/db/migrations/identity_v1.sql` is the canonical schema + analytical views (`v_identities`, `v_identity_pairs`, `v_identity_timeline`). `IdentityStore(backend="postgres", connection=...)` creates the same schema on first connect.
- **DuckDB / extensions contract**: the UDF signatures `packages/rust/extensions/` (Postgres pgrx + DuckDB) must expose. (The design doc that specified these was deleted; the SQL surface itself is the contract now, inventoried in `parity/goldenmatch.yaml`.)
- **Test count discipline**: Identity adds 47 Python tests (4 modules under `tests/identity/` + `tests/test_mcp_identity_tools.py` + `tests/web/test_router_identity.py`) and 13 TS tests (`tests/identity/`).
- **A2A skill count is 50** (`_SKILLS` in `a2a/server.py`). Update `test_agent_card_has_50_skills` in `tests/test_a2a.py` if you add a skill.
- **`pipeline.run_dedupe_df` result** now has `identity_summary: dict | None` (None when identity disabled).

### CDP/MDM epic (#1108)
Maturing Identity Graph v2 into a streaming, cross-channel, stewarded identity spine. Phases tracked under epic #1108 (label `cdp-mdm`, milestone "CDP / MDM Identity Resolution"). Each phase = one additive, opt-in PR; byte-identical / no-op when unused; no DB migration unless a phase needs one.
- **#1109 streaming/micro-batch incremental resolution (DONE, PR #1186):** `identity.resolve_record_incremental()` / `match_record_to_entity()` resolve ONE record at a time by delegating create/absorb/merge to `resolve_clusters` over a mini-frame (matched rows + the new row) — zero duplicated resolution logic. Wired into `core.streaming.StreamProcessor.resolve_to_entity`. `match_one` returns `[]` for exact matchkeys, so an exact-only incremental path is a follow-up.
- **#1110 cross-device / channel stitching (`identity/stitching.py`, PR #1210):** pure primitive in front of resolution, no DB migration. `classify_channel` (explicit `channel` col → `channel_map` source override → `__source__` substring hints → `unknown`) + `channel_trust` (crm 1.0 … web 0.5, unknown 0.6). `deterministic_stitch_pairs(df, device_keys)` STAR-links (not O(n²)) records sharing a non-null device key (`DEFAULT_DEVICE_KEYS`: cookie_id/device_id/login_id/…). `stitch_frame(df, scored_pairs=…, …)` unions the deterministic layer with the *caller-supplied probabilistic pairs* (it does NOT re-score) into channel-aware `StitchGroup`s; probabilistic edges are scaled by `cross_channel_factor` = geometric mean of the two channels' trust (deterministic device links are NOT downweighted), group `confidence` = weakest holding edge. Config: `IdentityConfig.stitching` (`ChannelStitchConfig`, default None/off); explicit kwargs to `stitch_frame` beat config fields. Tests: `tests/identity/test_stitching.py`.
- **#1111 survivorship learning + per-cell provenance (`identity/survivorship.py`, PR #1211):** `build_golden_with_provenance(df, member_row_ids, …)` rolls members up via `core.golden.merge_field` (reused, not re-implemented) and attaches a `CellProvenance` per column (source / source_row_id / timestamp / strategy / confidence) — every golden cell traceable. `learn_field_survivorship(corrections)` replays the learnable value-strategies over `FIELD_CORRECT` (original→corrected) pairs and reports, per field, the trust-weighted best strategy; `learned_field_strategies` filters to the confident subset as a `{field: strategy}` map. `most_recent`/`source_priority` need per-candidate dates/sources the correction doesn't carry (out of the learnable set). Config `IdentityConfig.survivorship` (`SurvivorshipConfig`). Tests: `tests/identity/test_survivorship.py`.
- **#1112 cross-run entity stabilization / Identity v3 (`identity/stabilize.py`, PR #1212):** `find_persistent_overlaps(store, min_runs=3)` flags entity pairs linked by cross-entity `same_as`/`possible_same_as` edges across ≥N DISTINCT runs (`conflicts_with` excluded — negative evidence). `stabilize_identities(store, winner_strategy=…, apply=False)` unions overlap candidates into components, picks a survivor (`most_records`/`oldest`/`newest`/`lowest_id`), and (apply) reassigns records + retires losers + emits the new `EventKind.CONSOLIDATED` (distinct from `MANUAL_MERGE`); dry-run by default. `entity_version(store, eid)` = count of structural events (canonical monotonic version). Config `IdentityConfig.stabilization` (`StabilizationConfig`). No migration (`consolidated` is a value in the existing `kind` column). Tests: `tests/identity/test_stabilize.py`.
- **#1113 conflict mediation (`identity/mediation.py`, PR #1213):** `conflicts_with` edges are INTRA-entity ("is this entity an over-merge?"). `open_conflicts(store)` = the conflict feed minus terminally-mediated pairs (deferred stay open). `mediate_conflict(store, a, b, resolution)` records a durable `EdgeKind.MEDIATION_VERDICT` edge (resolution in `negative_evidence`) + `EventKind.CONFLICT_MEDIATED` event: `same` keeps the entity, `distinct` splits `record_b` out via `manual_split` (when `apply`), `defer` logs only. `pair_verdict` / `mediation_summary` for state; verdicts dedup by canonical pair, latest-by-`recorded_at` wins (re-mediation uses a unique `mediation:<ts>` run_name to dodge the edge UNIQUE no-op). Added generic `store.edges_by_kind(kind)` (sqlite+mongo). Config `IdentityConfig.mediation` (`MediationConfig.auto_apply`). Tests: `tests/identity/test_mediation.py`.
- **#1114 distributed identity + MDM ops (`identity/profile.py`, PR #1214):** the *operate it* read-side (distributed resolve already exists in Phase 6 / `distributed/identity.py`). `entity_profile(store, eid)` (record/source breakdown, golden record, confidence, conflict count, structural-event `version`, first/last activity), `identity_summary_stats(store, dataset)` (by-status counts, records-per-entity distribution, source mix, largest entities), `steward_worklist(store)` (active entities with conflicts and/or weak confidence, prioritized). Surfaced via **3 new MCP tools** `identity_profile` / `identity_stats` / `identity_worklist` (IDENTITY_TOOLS 7→10, total MCP TOOLS 59→62 — update both count assertions in `tests/test_mcp_identity_tools.py` + `tests/test_mcp_new_tools.py` when touching). Read-only, no migration. Tests: `tests/identity/test_profile.py`.
