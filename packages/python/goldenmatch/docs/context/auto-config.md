## Auto-Config
- **Planning-effort tier (v1.28.0, spec `2026-06-06-autoconfig-search-strategy-after-engine-speedup-design.md`):** `planning_effort` ∈ {`fast`,`normal`,`thinking`,`einstein`} on `GoldenMatchConfig` + the `dedupe_df`/`match_df`/`auto_configure_df` kwarg + `GOLDENMATCH_PLANNING_EFFORT`. `ControllerBudget.for_dataset(n_rows, effort)` scales sample/iterations/wall (`_scaled_for_effort`); `resolve_planning_effort()` resolves kwarg→env→`normal`. **Default `normal` is byte-for-byte the prior behavior.** At `thinking`/`einstein` the controller calls `blocker.measure_blocking_profile(df, config)` to feed the planner MEASURED full-frame pair counts instead of `BlockingProfile.extrapolate_to` (Phase 1; falls back to extrapolation on the distributed path or any failure). `autoconfig_verify._check_remote_assets` exempts the in-house embedding model (`model="inhouse:..."` or `GOLDENMATCH_EMBEDDING_PROVIDER=inhouse`+`GOLDENMATCH_INHOUSE_MODEL`) from remote-asset demotion (`_is_local_embedding_field`); probe `embedder.inhouse_embedding_available()`. Phase 2 (successive-halving) + Phase 4 (LLM-judge labeling) are staged behind the tier seam, NOT yet built.
- `dedupe_df()` supports zero-config: calls `auto_configure_df(df)` when no exact/fuzzy kwargs
- `auto_configure_df(df)` in `core/autoconfig.py` — profiles DataFrame directly (no file I/O)
- `auto_configure(files)` delegates to `auto_configure_df` after loading files
- Classification: date/geo name heuristics are authoritative over data profiling
- Blocking safety: skips columns with >20% null rate, checks max block size (1000)
- Cardinality guards (v1.2.7):
  - Blocking: skips columns with cardinality_ratio >= 0.95 (near-unique, produces single-record blocks)
  - Matchkeys: skips exact matchkeys for columns with cardinality_ratio < 0.01 (too few distinct values)
  - Description columns: routes long text to fuzzy matching (token_sort) alongside embedding scorer
- **Probabilistic matchkeys admit identifiers (#721, 2026-06-05):** `build_probabilistic_matchkeys` no longer blanket-skips `col_type="identifier"` (it diverged from the exact path's #715 admission). Identifiers become exact-scorer comparison fields with **no lower cardinality floor** — unlike the exact path, Fellegi-Sunter self-regulates a weak identifier (higher `u` → smaller EM weight) instead of mega-clustering. The ONE hard gate is `cardinality_ratio >= 1.0` (perfect surrogate key, zero shared-identity signal), now applied **uniformly to every exact-scorer field** (identifier/email/phone). m/u estimation + blocking-field exclusion stay EM's job at train time (`train_em(blocking_fields=...)`), NOT the builder's.
- **FS auto-config v2 — comparison-set + blocking curation (2026-06-09, `GOLDENMATCH_FS_AUTOCONFIG_V2`, DEFAULT ON; `=0` restores legacy):** scoped to the PROBABILISTIC path only (`build_probabilistic_matchkeys` + `auto_configure_probabilistic_df`); the weighted/DQbench path is untouched. Four levers fix the auto-built Fellegi-Sunter comparison set that under-performed Splink on error-heavy PII and *catastrophically* mega-matched on bibliographic data: **(1)** admit `date` columns (dob) as `levenshtein` comparison fields (v1 dropped all dates — the strongest person discriminator); **(2a)** drop redundant person-name composites (`full_name`/`first_and_surname`) when atomic given+family fields are present (correlated comparisons violate F-S conditional independence, N-counting one name signal); **(2b)** floor fuzzy fields at `cardinality_ratio < 0.01` (drops a `gender`-like field at ~0.002 with non-monotonic EM weights; exact identifiers keep the #721 no-floor admission); **(3)** diversify blocking onto orthogonal stable keys (date YEAR via `substring:0:4` + postcode/zip/identifier passes, additive — the static blocker filters null block keys so high-null orthogonal keys form no giant null block); **(4)** admit `description` (title) + `multi_name` (authors) as `token_sort` fields (v1 left only a near-constant `venue` on bibliographic data → P~0). **MEASURED (scripts/bench_er_headtohead, GM probabilistic vs Splink, one evaluator): historical_50k F1 0.624→0.779 (Splink 0.757), febrl3 0.983→0.991 (0.965), synthetic 0.972→0.998 (0.996), dblp_acm 0.003→0.879 — i.e. beats Splink on every PII set and unbreaks bibliographic.** Precision holds ~1.0 except heavily-corrupted historical_50k (0.96→0.81, net F1 win). `GOLDENMATCH_FS_AUTOCONFIG_V2=0` is byte-identical to the legacy field set; `_fs_autoconfig_v2_enabled()` gates all four levers + the blocking helper. **Default flipped ON 2026-06-09** on the strength of the local v1-vs-v2 measurements (no measured regression on any of the four datasets); the `panel-v1-v2` lane in `.github/workflows/bench-probabilistic.yml` is the standing regression check (runs the panel under V2=0 and =1, diffs F1 per dataset via `scripts/bench_er_headtohead/compare_panels.py`, fetches DBLP-ACM from Leipzig). Tests: `tests/test_fs_autoconfig_v2.py` (24).
- **FS domain comparators — `date_diff` (2026-07-23, `GOLDENMATCH_FS_DOMAIN_COMPARATORS`, DEFAULT OFF; spec `docs/superpowers/specs/2026-07-23-fs-domain-comparators-design.md`):** a magnitude-aware date scorer for the FS path. The existing `date` scorer (Damerau-Levenshtein over ISO digits) is magnitude-BLIND — `1990-01-02` vs `1991-01-02` is one digit-edit → 0.90, over-scoring a full-year DOB gap. `date_diff` (`core/scorer.py::_date_diff_similarity_py`) parses both to a day-ordinal and bands by DAY-DISTANCE (`same→1.0, ≤1d→0.92, ≤31d→0.80, ≤1y→0.60, ≤5y→0.30`, else 0), with an MM/DD-transposition floor and an edit-distance (`_date_similarity_py`) fallback on unparseable input (so it never returns None for non-null strings). **Scale-neutral by construction:** it's just a new scorer — flows through the SAME `score_field` / `_fuzzy_score_matrix` routing (the vectorized NxN loop calls the SAME scalar fn → scalar==vectorized parity automatic) and the SAME level machinery, so blocking, the pair set, memory, EM shape, and clustering are all unchanged (declines `_fs_native_eligible` → numpy path, like `soundex_match`). Auto-config admits `date` columns as `date_diff` (partial_threshold 0.6) ONLY under the flag; default-off is byte-identical (dates stay `levenshtein`). Flip the default only after the `bench_er_headtohead` panel lift + `qis_gate` scale-neutrality, per the v2-flag precedent. Tests: `tests/test_date_diff_comparator.py` (18) + 2 in `test_fs_autoconfig_v2.py`.

- **FS orthogonal-anchor blocking (2026-07-25, `GOLDENMATCH_FS_ORTHOGONAL_BLOCKING`, DEFAULT `auto` = person-data-gated):** a field-agnostic generalization of v2 lever #3 (`_diversify_unused_orthogonal_blocking` in autoconfig.py). v2's diversify only adds passes for `date` + `zip`/`identifier`/`phone` col_types; the strongest orthogonal anchor a dataset carries may be classified as something else — on historical_50k `birth_place` profiles as `name` (null 0.13, sampled card 0.48), slips past that whitelist, and blocking keys entirely on the corrupted name composites (blocking_recall caps ~0.78). This rule selects by DATA SHAPE not col_type: any field with `null_rate <= _ORTHO_BLOCK_NULL_CEILING(0.4)` and `cardinality_ratio in [_ORTHO_BLOCK_CARD_FLOOR(0.02), _ORTHO_BLOCK_CARD_CEILING(0.9))` that no existing pass already keys on earns a single-field `strip` pass. **The load-bearing design decision is `additive=True` (new `BlockingKeyConfig` field):** adding a field as a blocking key normally DEMOTES it from EM to a fixed neutral weight ramp (`collect_blocking_fields` → `train_em(blocking_fields=)`); demoting a strong name discriminator (first_name/surname) collapses recall outright (measured B³ 0.808→0.561, clusters TRIPLE). `additive` passes co-locate pairs WITHOUT demoting — `collect_blocking_fields(config, for_em=True)` (the 3 EM-demotion call sites in pipeline.py: `_score_probabilistic_matchkey` ×2 + the streaming FS path) excludes a field confined to additive passes so it stays EM-trained (a field ALSO in a primary pass is still demoted; no-additive config → `for_em` is byte-identical to the default). EM's per-pass block provenance conditions out each pass's own always-agree bias, so an additive anchor learns its weight from the OTHER passes' pairs. blocking_recall 0.779→0.932 on historical_50k; kept-in-EM beats demoted (0.866 vs 0.852 B³) and demoting the name fields is the catastrophe. **DEFAULT is `auto` — the DATASET-TYPE GATE (`_dataset_is_person_shaped`: a `name` col_type AND a `date` col_type both present):** the lever GENERALISES on person data but REGRESSES on bibliographic/product (there the "anchor" venue/year is a TOPIC bucket — it co-blocks + adds match weight while the only real discriminator, a noisy title, can't reject the false pairs → SCORING over-merge, venue's blocks are tiny so NO block-size guard separates the regimes; isolated, venue alone drops pw_F1 0.329→0.011). `name AND date` cleanly separates the validated regimes (dblp_scholar/amazon_google carry NEITHER — title=description, authors=string, year=year). **Validated `0`(forced-off) vs `auto`:** person historical_50k F1 0.826→0.847 (B³ 0.808→0.873), febrl3 0.987→0.994, **febrl4 holdout 0.989→0.995**; **non-person dblp_scholar 0.3293→0.3293 and amazon_google 0.0598→0.0598 — ΔF1 EXACTLY 0 (auto no-ops, byte-identical)**, so the −0.24 dblp_scholar regression that would come from a blanket flip is eliminated. `=1` forces everywhere (the pre-gate behavior, useful to force a misclassified person set); `=0` disables (byte-identical to the pre-lever field set). Mode resolver `_fs_orthogonal_blocking_mode()` mirrors the `GOLDENMATCH_NATIVE=auto/0/1` tri-state.
