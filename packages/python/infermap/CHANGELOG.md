# Changelog

## [Unreleased]

### Fixed
- **A fact's own party is no longer stop-listed, and a lone key no longer invents one** -- layer detection **92% -> 100% exact partition** on the FK-derived corpus, with precision-corpus specificity and sensitivity both held at 100%. Two changes that only work together. (1) `claim` is declared as a role in `healthcare` and `insurance`. It tokenizes out of their `claim_status` / `claim_number` field-type hints, so the kernel stop-listed it and the fact's own columns were dropped -- the three *dimension* parties in `claims_ledger` scored 0.90-0.93 while `claim_claimnumber` / `claim_lossdate` / `claim_paidamount` landed in `unassigned`. This was recorded as a known miss in 0.7.0 and is the same `name_hints`-suppression class fixed there for nine other packs; `stop -= role_tokens` is the only escape. `kind: asset` follows `product` / `vehicle`, `IDENTITY_KINDS` being closed. (2) A single-column group is now viable only when the token IS the whole column (`bank`, `lender`), not when it is a prefix or suffix with a remainder. Declaring the role alone regressed partition sensitivity 100% -> 86%, because a lone `claim_id` then opened a one-column party. The two independently labelled corpora turn out to agree on this: the precision corpus leaves the fact's key uncovered in **6 of 6** positives, and the FK corpus only calls a fact a party when it contributes several columns. Accepting any recognised single column satisfied neither. Cost: `plant_code` alone no longer reports a `place` party -- asserted on a two-column plant instead, so the kind is still pinned. Mirrored across all four surfaces (Rust kernel, Python fallback, TypeScript, WASM); one oracle case re-pinned. The FK floors move to exactly 1.0: that corpus has now **saturated on detectable conventions**, and the discriminating signal moves to the `initial` convention (single-character qualifiers, still 0%) and the blind-labelling corpus. (#2574)

## [0.7.0] - 2026-08-15

### Added
- **A blind-labelling corpus for layer detection** (`scripts/layers_blind_label.py`, `tests/fixtures/layers_blind_labels.json`). The two existing corpora were both built inside this workstream -- one hand-authored by whoever tuned the detector, one mechanically labelled but from generated tables -- and both now score at or near ceiling, which means they have stopped discriminating. This is the third instrument and the only one whose labels come from outside: real column names, grouped by a human who has not seen what the detector says about them. `worksheet` samples real schemas (diversity-filtered by token-set Jaccard and capped per source directory, after two earlier filters both produced a sheet dominated by one benchmark generator) and **never imports the detector** -- enforced by a test, because a worksheet carrying predicted groupings would anchor the labeller and turn this into a third measure of self-agreement. `score` reuses the FK harness's partition metrics so all three corpora stay commensurable. Ships unlabelled: scoring reports "awaiting labels" and the test skips, which is a normal state rather than a failure. `--from-dir` points the sampler at real schemas elsewhere, which is how it earns its keep -- sampled from this repo it draws on library test fixtures, a deliberately weak substitute for production data.

### Fixed
- **Field types no longer suppress the parties they name** -- layer-detection *sensitivity* **71% -> 100%** on the precision corpus. A field type's `name_hints` land in the kernel's stop-list so a token like `account` cannot open a phantom party; the escape hatch is that a **role declaration overrides the stop-list**. Packs with no `roles:` block had no way to use it, so any party name that happened to appear in a type hint was permanently undetectable. Auditing all 16 packs found this in **9 of them**: `legal` was the starkest -- its `parties` type hints `plaintiff`, `defendant`, `attorney` and `counsel`, and `court` is its own type, so every party the vertical has was suppressed. Also `hr` (`employee`/`staff`/`manager`/`supervisor`), `logistics` (`consignee`/`carrier`/`warehouse`), `marketing` (`lead`, hinted by three separate types), `education` (`student`), `energy` (`utility`), `hospitality` (`guest`), `telecom` (`subscriber`), `ecommerce` (`carrier`). The 11 packs lacking a `roles:` block now declare one, which both lifts the suppression and gives those verticals a party vocabulary they never had.

### Added
- **Foreign-key-derived ground truth for layer detection** (`layers_fk_schemas.json`, `scripts/layers_fk_groundtruth.py`, `tests/test_layers_fk_groundtruth.py`). The hand-authored precision corpus could not rule out overfitting -- its labels were written by whoever tuned the detector. Here nothing is hand-labelled: wide tables are generated by joining a fact to its dimensions in reconstructed public schemas (TPC-H, Northwind, Sakila) and **a column's party is simply the table it came from**, so the grouping is the original schema designer's. Scored by exact partition and by pairwise F1 over column pairs (partial credit, so a near-miss partition is distinguishable from a rout). **Result: 92% exact partition, 0.99 pairwise F1, mean party-count error 0.08** across four renaming conventions -- independent confirmation that the hand corpus was not being overfit. Two findings recorded rather than smoothed over: single-character qualifiers are a **hard blind spot** (TPC-H's own `c_name`/`s_name` style is below the kernel's `MIN_QUALIFIER_LEN`, so those schemas cannot be segmented by name at all -- pinned as a test so a future fix is noticed), and the one systematic miss reproduces the `name_hints`-suppression bug independently: `claim` is a healthcare *type* hint, so `claim_*` columns cannot form a party under the `full` convention while `clai_*` groups fine.
- **A precision corpus for identity-layer detection, and the baseline it measures.** The existing layer corpus was authored alongside the detector's semantics, so it could not measure precision -- it encodes the assumptions it tests. `tests/fixtures/layers_precision_corpus.json` is labelled from each schema's *naming convention* instead: negatives are single-entity tables whose columns share a qualifier for a reason that is not a party (warehouse lineage, the table's own name, audit trails, units of measure), positives are genuinely multi-party tables. Both halves are load-bearing -- a negatives-only corpus is scored 100% by a detector that never splits anything. `scripts/layers_precision.py` reports the numbers; `tests/test_layers_precision.py` pins them as a ratchet. **The measured baseline is poor and recorded honestly: 56% specificity (the detector invents a party on 7 of 16 single-entity tables) and 71% partition sensitivity.** The floors exist so it cannot get quietly worse; raising them is the point.
- **A cross-vertical party vocabulary, unioned into every pack's roles.** `generic` gained a `roles:` block (customer / user / employee / person / owner / organization / vendor / location / product), and both hosts now append it to whatever the detected vertical declares. This closes two measured gaps: `detect_domain` finds no vertical for the overwhelming majority of real schemas, which loaded **no pack at all** — detection grouped a frame's columns into parties correctly and then had nothing to NAME them with — and a frame that *does* resolve to a vertical still contains parties that vertical never enumerates (`finance` declares lender / borrower / payee but no plain `customer`, so `customer_id`/`customer_name` came back `unknown` on a table the pack otherwise understood well). Measured over 155 distinct real schemas in the repo: layers carrying a named party went from 1 to 33, and schemas with at least one named party from ~1% to 19%. The union is additive and the **vertical wins collisions** — pack roles keep their position at the front and a generic role whose name the pack already declares is dropped, so a vertical's reading of a shared token always takes precedence. Safe by construction: `generic` declares no field *types*, so it contributes role names only and cannot widen the kernel's attribute stop-list (a test pins that no declared generic hint collides with `ATTRIBUTE_TOKENS`, since a role declaration overrides that stop-list and would re-open the cross-party fusion it was added to fix).
- **Identity-layer detection** — `detect_identity_layers(df)` reports which *parties* a frame refers to (lender, borrower, payor, machine, patient…), as distinct from `detect_domain`, which reports the single industry vertical. A layer is a **group of columns describing one party**, so detection is column-grouping rather than per-column classification and never touches the deliberately 1:1 mapping assignment. Two signals: affix clustering (primary, domain-free — works on schemas no pack has seen) corroborated by an optional `roles:` block in domain packs. Unrecognised parties are reported with `role="unknown"` and their evidence rather than dropped or force-fit; columns in no layer land in `unassigned`. Reads column names only. `detect_domain` behaviour is unchanged.
- **The layers kernel is Rust-authoritative.** `infermap-core::detect_identity_layers` owns every semantic choice (attribute stop-list, role-override precedence, viability guards, scoring, assignment, singleton fallback); Python (`infermap[native]`) and TypeScript (`enableInfermapWasm()`) are thin callers over the same kernel, with byte-identical pure implementations as classified fallbacks — the arrangement `detect_domain` already uses. Hosts do domain-pack loading and result mapping only. Plain-list signature rather than Arrow: a few hundred column names is the small-call case. Scores are returned unrounded on every surface, because Python/Rust/JS rounding disagree at exactly the midpoints a 4-decimal score lands on. Parity is pinned by a kernel-generated oracle (`tests/fixtures/layers_parity.json`) that the Python and TypeScript fallbacks are both asserted against.
- **`layers` reaches the MCP and CLI surfaces on both languages.** `infermap layers <source> [--domain <name>]` and the `layers` MCP tool report the detected parties with their kind, score, evidence and the columns belonging to no party. Python and TypeScript emit byte-identical output. Declared in `parity/infermap.yaml` in the same change, since the `api_parity` gate requires the tool, the command and the manifest entry to move together.
- Domain packs gained an optional `roles:` block (`finance`, `insurance`, `healthcare`, `manufacturing` declare them). `goldencheck-types` `SCHEMA_VERSION` 3 -> 4: new `RoleSpec`, `IdentityLayer`, `LayerDetectionResult`, `IDENTITY_KINDS`, `LAYER_REASONS`, `UNKNOWN_ROLE`, and `DomainPack.roles`, mirrored in the TypeScript sibling. The block is additive — packs without it load unchanged.

### Fixed
- **Lineage, audit and aggregate qualifiers no longer open a party** -- layer-detection specificity **56% -> 100%** on the precision corpus. The kernel's `ATTRIBUTE_TOKENS` stop-list gained three groups, each added because the corpus caught it inventing a party on a single-entity table, not because it seemed plausible: lineage (`src`/`etl`/`stg`/`raw`/`batch`/`ingested`/`extracted`/`loaded`), audit (`approved`/`reviewed`/`submitted`/`verified`/`deleted`/`inserted`/`processed`, siblings of the `created`/`updated`/`modified` already there) and aggregate/unit (`avg`/`mean`/`median`/`sum`/`pct`/`usd`/`eur`/`gbp`, joining `total`/`count`/`qty`). Provenance was the worst class at 1 of 5 correct -- `src_id`/`src_assay_id` beside a real entity produced a phantom "src party" on every staging table. **A confidence threshold was measured first and rejected**: true and false parties overlap almost exactly in score (true 0.475-0.775, false 0.475-0.650), because the score measures how *affix-y* a group is, not how *party-y* -- the discriminating signal is which token it is, so a stop-list is the right instrument and a threshold is not. Sensitivity is unchanged (71%), so the precision was not bought by suppressing real detection; across 155 real schemas, multi-layer detections fell 31 -> 21 while named parties held at 33. The kernel owns the list with both fallbacks mirroring it, and a role declaration still overrides it, so a pack that genuinely means one of these as a party can say so.

## [0.6.0] - 2026-07-16

### Added
- **Compiled Rust scorer kernels** (`pip install infermap[native]`). The five scorers (exact, fuzzy-name, initialism, profile, pattern-type) and `detect_domain` now share a pyo3-free Rust core (`infermap-core`), wrapped by the abi3 `infermap-native` wheel. Under the default `INFERMAP_NATIVE=auto` the scorers auto-dispatch to the compiled kernels when the wheel is importable, else the pure-Python reference — byte-identical, CI parity-gated. `INFERMAP_NATIVE=1` requires native (raises if absent); `=0` forces pure Python.
- **TypeScript WASM backend** — the same `infermap-core` kernels compiled to WASM (`infermap-wasm`), exposed as an opt-in backend via `enableInfermapWasm()`. Pure-TS stays the default + byte-identical fallback. The MCP servers enable it best-effort at startup and report the active backend through the `infermap://scorer-info` resource (Python: `native`/`pure-python`; TS: `wasm`/`pure-ts`).
- Top-level re-export of `detect_domain_detailed` on the TypeScript surface (parity with Python).

## [0.5.1] - 2026-06-24

### Security
- **SQL-injection hardening in `DBProvider`** (#898). Table names are now escaped as quoted SQL identifiers (`_quote_ident`, doubling embedded quotes) at every interpolation site across the SQLite, Postgres, and DuckDB paths, since bound parameters can only bind values, not identifiers. `extract()` now rejects a non-string `table` and coerces `sample_size` to `int` before it can reach a query. SQLite column introspection moved from `PRAGMA table_info(<ident>)` to the parameterized `pragma_table_info(?)` table-valued function. `sample_size` is bound as a parameter on SQLite/Postgres (int-coerced inline only on DuckDB's `USING SAMPLE`).

### Changed
- Node runtime baseline bumped from 20 to 22 (Node 20 EOL) across the JS publish/CI workflows. (#898)
- Dependency bumps: `esbuild` 0.27.7 → 0.28.1, `@babel/core` 7.29.0 → 7.29.6 (#1162); TS bench-runner `vitest` 1.6 → 4.1 (#761).

## [0.3.0] - 2026-04-10

### Added
- **Valentine corpus** — 82 real-world schema-matching cases extracted from the Valentine benchmark (BSD-3-Clause, Zenodo). Subcategories: Magellan (7), ChEMBL (25), OpenData (25), TPC-H (25). `infermap-bench rebuild-manifest` is now implemented (was a stub).
- **Confidence calibration** — `MapEngine(calibrator=...)` (Python) / `MapEngine({ calibrator })` (TypeScript). Post-assignment only: relabels confidence without changing which mappings are picked. Ships `IdentityCalibrator`, `IsotonicCalibrator` (PAV), `PlattCalibrator` (Nelder-Mead). JSON round-trip via `kind` discriminator. ECE on Valentine: 0.46 → 0.005 with isotonic.
- **`InitialismScorer`** — new scorer that matches abbreviation-style column names (e.g. `assay_id ↔ ASSI`, `confidence_score ↔ CONSC`). DP-based prefix-concat matcher. Abstains on non-matches. Weight 0.75. ChEMBL F1: 0.524 → 0.819.
- **Common-prefix canonicalization** — `FieldInfo.canonical_name` (Python) / `canonicalName` (TypeScript). Engine strips schema-wide common delimiter-bounded prefixes/suffixes before scoring so `City` vs `prospect_City` becomes `City` vs `City`. Deep-copies input schemas (no caller mutation).
- **Domain dictionaries** — curated alias YAMLs for `healthcare`, `finance`, `ecommerce` shipped with the package. `MapEngine(domains=["healthcare"])` loads them. Generic domain loaded by default. `infermap.yaml` gains a `domains:` key. `mrn ↔ patient_id` confidence: 0.27 → 0.95 with healthcare.
- `infermap-bench calibrate` CLI subcommand — fits a calibrator from labeled cases, reports holdout/full ECE.
- `infermap-bench run --calibrator cal.json` — applies a fitted calibrator during benchmark runs.
- New examples: `09_domain_dictionaries.py`, `09_domain_dictionaries.ts`, `10_calibration.py`.
- Documentation: `docs/domain-dictionaries.md` (Pages).

### Changed
- **Default `min_confidence` lowered from 0.3 to 0.2.** Empirically tuned on the combined Valentine + synthetic corpus. Combined F1: 0.657 → 0.765. Users who prefer the old behavior can pass `min_confidence=0.3` explicitly.
- **TypeScript parity** — all new features (calibration, prefix-norm, InitialismScorer, domain dictionaries) ported to TypeScript. Benchmark F1 within 0.0005 of Python; synthetic slice is bit-identical. 186 TS tests.

### Fixed
- Calibrator deserialization hardened: `IsotonicCalibrator.fromJSON` and `PlattCalibrator.fromJSON` now throw on malformed input instead of silently falling back to defaults.
- Calibrator output validated: engine throws if `transform()` returns wrong length or non-finite values.
- `isPrefixConcat` DP guarded against pathological inputs (max 200 chars target, 50 source tokens).

## [0.2.0] - 2026-04-09

### Added
- **Cross-language accuracy benchmark** (`benchmark/`) — manifest-driven case corpus, hand-anchored metrics (F1, top-1, MRR, ECE), Python and TypeScript runners with bit-identical scoring on the v0.1 scorer set, and a self-test corpus that gates CI.
- **`MapEngine.map_schemas()`** (Python) / **`MapEngine.mapSchemas()`** (TypeScript) — pre-extracted-schema entry point that bypasses provider re-extraction. Use this when you already hold a `SchemaInfo`.
- **`return_score_matrix=True`** flag — exposes the full M×N candidate score matrix on `MapResult.score_matrix`, enabling MRR computation, runner-up inspection, and override UIs.
- Synthetic case generator with deterministic seeding (Python is canonical; TypeScript loads the committed JSON).
- Regression-gating CI: PRs that drop F1 by more than the threshold require an explicit `regression-ack` label.
- New examples: `08_benchmark_introspection.py` and `typescript/08_score_matrix_introspection.ts`.
- Documentation: `docs/benchmark.md` (rendered on the docs site).

### Fixed
- Cross-language drift on the synthetic slice (~25pp F1 gap → 0.3pp): the Python engine was round-tripping `SchemaInfo` through polars and re-inferring dtypes; `map_schemas()` is the supported way to avoid that.
- `MapEngine.map_schemas()` now deep-copies the target schema before merging schema-file aliases (no caller mutation).
