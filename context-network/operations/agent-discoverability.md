## Agent discoverability: every distributable ships an `llms.txt` (2026-08-08)
The problem: agents working in OTHER repos reverse-engineer what a Golden Suite package does instead of querying its docs — because an INSTALLED artifact (`site-packages/goldenmatch/`, `node_modules/goldenmatch/`, a SQL connection, a checked-out action) had nothing to read. Docs that only exist in this repo don't help someone who never clones it. **Standing rule: every distributable surface ships an `llms.txt` INSIDE the artifact**, plus `Documentation` + `"AI agents (llms.txt)"` URLs (PyPI/npm render and scrape these) and an AUTHORITATIVE SOURCES block opening the module docstring / `//!` crate docs. Gated by `check_docs_consistency.py::check_agent_pointers` (per-ecosystem path rule + a declared `_LLMS_DEFERRED` map in the `scorer_kernels_deferred` style) — a new package with neither a pointer nor a stated reason FAILS. Full arc + per-ecosystem rules: `context-network/planning/discoverability.md`.
- **An `llms.txt` in the repo reaches nobody until that package cuts a RELEASE.** The whole point is the file being inside the *installed* artifact, and every currently-published wheel predates the sweep — verified 2026-08-09 by unzipping the latest published goldenmatch / goldencheck / goldenanalysis wheels: `llms.txt` ABSENT in all three. So the arc is only half-delivered until each distributable ships a version built after 2026-08-08. Check before assuming a package is covered: `pip download <pkg> --no-deps -d /tmp/x && unzip -l /tmp/x/*.whl | grep llms.txt`.
- **The docs site is served under a `/docs` prefix.** The bare host 308s to `/docs`; a path without it is a **404**. All 135 `docs.bensevern.dev` URLs in the repo omitted it, so the whole pointer network was dead links (worse than no pointer — a 404 sends the reader back to the source). Mintlify auto-generates the index at **`/docs/llms.txt`**. Now gated repo-wide by `check_docs_links.py`, statically (no network in CI).
- **`.gitattributes` marks `**/llms.txt` as `-diff`, so git treats them as BINARY and `git grep -I` SKIPS EVERY ONE.** Bit twice in one sitting: a repo-wide rewrite driven by `git grep -lI` updated 89 files and silently skipped all 31 llms.txt, and the gate written to catch that used the same `git grep` — passing while blind to exactly the files it existed to check. **Any repo-wide sweep touching llms.txt must enumerate with `git ls-files` and decide text-ness itself.** The gate now also fails if it reads <10 llms.txt carrying a docs URL: a scan that finds nothing must look BROKEN, not clean.
- **SQL has no filesystem, so it gets a function:** `goldenmatch_docs()` returns the packaged `llms.txt` on both backends (DuckDB reads the file; pgrx `include_str!`s it, so it is `IMMUTABLE PARALLEL SAFE` and answers even where the embedded-CPython bridge would fail to initialise).
- **Python: move the file INTO the importable dir; do NOT `force-include` from the package root** — that re-adds an already-collected path and fails the build with "Duplicate filename in local headers" (broke the v1.7.0 publish). force-include IS right when the source sits OUTSIDE the package dir (the dbt package does this).
